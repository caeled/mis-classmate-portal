Open weights are only one part of openness

Separate access to weights, training code, training data, evaluation code, and license permissions. A downloadable artifact can carry restrictions. A third-party quantization can add provenance questions. Record the upstream repository, revision, checksum, license, and intended use before an experiment.

Local deployment: what changes?

  • Choose a runtime that explicitly supports the selected architecture and chat template. Start with a small public-data experiment.
  • Estimate memory for weights, runtime overhead, and the key/value cache. A rough weight-only estimate is parameters × bits per parameter ÷ 8; actual memory is higher and depends on implementation.
  • Measure time to first token, generation speed, peak memory, and accuracy at your chosen context length. A model that loads may still be too slow for the workflow.
  • Treat quantization as a quality/cost experiment, not a lossless transformation. Compare edge cases and structured output at each precision.
  • Secure the serving endpoint and review remote tools, logging, and telemetry. “Local” does not automatically mean no data leaves the device.
  • Budget staff time for version updates, incident response, and hardware utilization. A zero per-token invoice is not zero operating cost.
  • Ollama — Desktop and application model use.
  • vLLM — Serving infrastructure for supported models.
  • PagedAttention paper — Research on memory management for model serving.
  • LoRA paper — Parameter-efficient adaptation; tuning does not replace a current evidence source.
