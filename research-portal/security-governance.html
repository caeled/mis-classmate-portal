Why Security Matters in MIS

Management Information Systems depend on trustworthy, authentic, and confidential data. If information is stolen, altered, lost, or made unavailable, core operations halt and executive decisions are severely compromised.

Security and governance provide the strategic controls, technical defenses, and oversight frameworks necessary to mitigate risk and maintain regulatory compliance.

The CIA Security Triad

Principle Definition Key Controls
Confidentiality Only authorized users, systems, and processes can view sensitive data. End-to-end encryption (AES-256), Role-Based Access Control (RBAC), Data Loss Prevention (DLP)
Integrity Information remains complete, unaltered, and protected against unauthorized tampering. Cryptographic hashing (SHA-256), digital signatures, database transaction ACID logs
Availability Systems, networks, and applications are reliably accessible to authorized users when needed. Geographic cloud redundancy, automated failover, DDoS mitigation (Cloudflare), RAID storage

Information Security Threats & Threat Vectors

  • Malware & Ransomware: Malicious software encrypting corporate assets for extortion. Tracked by MITRE ATT&CK Framework.
  • Phishing & Social Engineering: Deceptive campaigns harvesting credentials and bypassing perimeter defenses.
  • Credential Theft & Account Takeover: Exploitation of compromised or reused passwords. Mitigated by FIDO2 WebAuthn keys.
  • Insider Threats: Unauthorized data exfiltration or system sabotage by internal employees or contractors.
  • Cloud Misconfiguration: Insecure S3 buckets, exposed ports, and overly permissive IAM roles.
  • Supply Chain Attacks: Compromises in third-party libraries and vendor software dependencies.

Identity and Access Management (IAM)

Identity is the new perimeter in modern distributed and cloud environments. Organizations must enforce strict authentication and granular authorization.

Core IAM Concepts & Tools

  • Authentication (AuthN): Verifying user identity via FIDO2 / WebAuthn and Multi-Factor Authentication (MFA).
  • Authorization (AuthZ): Granting granular permissions via Role-Based Access Control (RBAC) and Attribute-Based Access Control (ABAC).
  • Single Sign-On (SSO): Federated authentication protocols including OpenID Connect (OIDC) and SAML 2.0.
  • Enterprise Identity Providers: Centralized directories managed by Microsoft Entra ID and Okta.
  • Conditional Access: Dynamic evaluation of user risk score, device health, and geographic location before granting access.

Zero Trust Security Architecture

Zero Trust replaces implicit network trust with an explicit, continuous verification mandate:

Never trust. Always verify. Assume breach.

Published and standardized by the National Institute of Standards and Technology in NIST SP 800-207: Zero Trust Architecture.

Three Fundamental Zero Trust Principles

  • Verify Explicitly: Always authenticate and authorize based on all available data points (identity, location, device health, service or workload).
  • Use Least Privilege Access: Limit user access with Just-In-Time (JIT) and Just-Enough-Access (JEA) models to protect data and productivity.
  • Assume Breach: Minimize blast radius through network micro-segmentation, encryption in transit and at rest, and automated threat detection.

Artificial Intelligence Governance & Safety

The rapid enterprise deployment of generative AI has created urgent new governance demands:

  • AI Risk Management: Governed by the NIST AI RMF (Risk Management Framework).
  • Prompt Injection & Jailbreaking: Documented in the OWASP Top 10 for Large Language Models.
  • Data Leakage Prevention: Enforcing strict boundaries so confidential customer or code data is never ingested into public model training sets.
  • Hallucination & Provenance: Implementing strictly grounded Retrieval-Augmented Generation (RAG) and digital watermarking (C2PA Standard).
  • European Union AI Act: The world's first comprehensive legal framework regulating AI systems by risk category (EU AI Act Overview).

Cloud Shared Responsibility Model

Cloud Service Layer Cloud Provider Responsibility (e.g. Azure / AWS / GCP) Enterprise Customer Responsibility
IaaS (Infrastructure as a Service) Physical datacenters, server hardware, hypervisors, and core cables Operating system patching, network firewalls, IAM roles, and application data
PaaS (Platform as a Service) OS maintenance, database engine runtime, and hardware scaling Application code, API security configurations, and user authentication
SaaS (Software as a Service) Application availability, underlying software code, and infrastructure User access permissions, data governance, and account credential security

AI controls to test, not just name

  • NIST AI RMF — Organize risk ownership and evaluation across the AI lifecycle.
  • OWASP GenAI Security Project — Study prompt injection, excessive permissions, data exposure, and insecure output handling.
  • Official GDPR text — Primary legal text; gdpr.eu, linked in the original page, is not the EU’s official portal.
  • European Commission AI Act page — Official starting point for applicability and implementation updates.
  • Enforce document permissions before retrieval; a prompt telling the model to ignore confidential data is not access control.
  • Treat retrieved pages and tool output as untrusted data. Validate tool arguments and require human review for consequential external actions.
  • Measure unsupported claims and citation accuracy. RAG and a citation requirement do not guarantee truth.
  • Check storage, retention, training use, region, subprocessors, and connector behavior for the exact service and contract. Local weights alone do not secure an application.
  • Content provenance can document an asset’s history; it does not prove that its factual claims are true.

Research note: the original legal table is a simplified orientation, not a complete statement of obligations. Consent is not the only GDPR lawful basis; breach notification and erasure have conditions and exceptions. Consult the applicable primary text for a specific case.
