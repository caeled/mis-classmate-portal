Choose a model with a reproducible experiment

Suggested student protocol: 20 cases, two candidate systems, and a non-AI baseline. Use 12 normal cases, four missing/conflicting-evidence cases, and four boundary cases. These counts are a teaching design, not a statistically sufficient sample for production approval.

  • Write an answer key from verified source material before running the models. Keep evaluation cases separate from prompt-tuning examples.
  • Hold the corpus, task, tool access, and output schema constant where possible. Record any unavoidable differences.
  • Capture exact model version, host, prompt revision, reasoning setting, generation settings, tool calls, runtime, token usage, and date.
  • Blind-review correctness and source support. Repeat a subset to expose variability and report sample size.
  • Investigate failures by stage: ingestion, retrieval, generation, tool use, or user-interface misunderstanding.
  • Choose thresholds before seeing results. For consequential tasks, include human review and domain-specific validation.

Token-cost estimator

Example assumptions only; enter the current rates for your selected service.

Formula: requests × (input tokens × input rate + output tokens × output rate) ÷ 1,000,000. Excludes caching discounts, extra reasoning usage not included in your output estimate, tools, search, storage, retries, taxes, and staff time. No API calls are made.

Benchmarks: useful but bounded

  • SWE-bench — Software issue-resolution benchmarks. Results include the agent scaffold and tool configuration, not just a bare model.
  • Stanford HELM — A broader evaluation framework; inspect each scenario and metric.
  • BIG-bench research — A study of diverse model capabilities.
  • Lost in the Middle — A reason to test long-context behavior with your own evidence placements.

Check benchmark version, data contamination risk, inference budget, tools, sampling, and whether the evaluation is independently reproducible. Human preference is not the same as factual accuracy. Never combine incomparable leaderboard scores into a universal ranking.

A practical selection matrix

  • Current research: prioritize source access, citation checking, and the ability to mark unknowns.
  • Permissioned enterprise knowledge: prioritize access-aware retrieval, retention settings, and auditability.
  • High-volume extraction: prioritize schema validity, exact-field accuracy, latency, and cost per accepted record.
  • Coding: prioritize passing independent tests, secure tool execution, and reviewable changes.
  • Local/offline work: prioritize supported hardware, license, reproducibility, and operational ownership.
  • Multimodal work: test the exact input/output modalities and representative documents, not only generic chat.
